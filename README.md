开源扫码点餐多门店系统技术架构总览
本系统主要应用于餐饮行业，特别适合早餐店、面馆、快餐店、零食小吃等快捷扫码点餐场景。核心特点是支持先付后就餐和先就餐后付费两种模式，满足不同餐饮业态经营需求。系统采用多门店架构，支持匹配附近店铺、堂食叫号、外卖带走、菜品管理、多门店数据汇总等完整功能，是100%开源的扫码点餐解决方案。

系统后端采用PHP开发，前端基于Uniapp实现微信小程序多端覆盖。数据库选用MySQL，缓存层使用Redis提升高并发查询性能。微信小程序端支持用户自动登录和手机号登录两种方式，Uniapp同时承载用户端、商家中心和店员端三个角色入口，一套代码实现多端协同。订单打印集成芯烨云打印实现下单后自动出票。

分层架构：表现层（Uniapp小程序）、接口层（RESTful API）、业务逻辑层（服务类）、数据访问层（模型层）、数据存储层（MySQL+Redis）。接口层统一返回JSON格式便于前端解析和错误处理。业务逻辑层按模块划分为门店服务、菜品服务、订单服务、支付服务、会员服务、分销服务等，各服务低耦合高内聚。

核心数据表：门店表（store）存储门店名称地址经纬度营业状态；菜品表（product）存储菜品名称价格规格备注选项；门店菜品关联表（store_product）实现多门店公用相同菜品；订单表（order）统一收口所有门店订单通过store_id区分归属；会员表（user）存储用户信息积分钱包余额；分销关系表（distribution）记录上下级关系。多门店公用菜品通过“总部菜品库+门店关联”设计实现，总部维护标准菜品库，门店选择上架并在允许范围内调整价格库存。

系统功能涵盖扫码点餐（桌码绑定叫号取餐）、外卖带走（手机号输入支付后取餐）、菜品管理（多规格备注）、多门店管理（独立管理+数据汇总）、积分商城（消费得积分兑换）、优惠券（促销提高粘性）、订单打印（芯烨云打印）、提前预约（到店直接就餐）、钱包储值（增加粘性）、二级分销（推广得佣金）、商家中心（在线接单）、店员端（角色权限管理）。开源特性为餐饮商家和开发者提供极高二次开发自由度。
